# 项目模型预算与计量

2026-10-30，P1.5。实现范围为项目规划、重新规划和自动研究 SDK 的 Responses 请求；科研质量、搜索覆盖、实验设计和最终报告仍按实施计划分别验收。

## 记录与默认值

项目 `budget.json` 使用 `dsh-sci.research-budget.v2`，沿用 Repository 原子替换和可选元数据加密。默认新项目为 100 次任务执行、首次任务执行起 1 小时、100 次模型请求预留、已报告 token 达到 1,000,000 时停止后续调用。可信调用方可在创建时指定限制；工作区可修改额度。

v2 同一文件保存以下内容：

- 原任务/时间额度、已用次数、首次执行时间、revision 和耗尽原因。
- 模型请求额度、已预留次数、input/output/total token 汇总、未知 usage 次数。
- 每次 reservation 的 ID、阶段、计划/任务/attempt、预留/结算时间、usage 和中断标记。

模型账本只接受明确的 scope 字段，不保存请求正文、响应内容、headers、密钥或原始错误。读取时核对 ledger 与汇总计数、安全整数、项目归属、重复 ID 和结算状态；不一致会阻止继续预留，不重置预算。

## 预留与结算语义

每次网络尝试前先持久化预留。预留、计数和结算状态使用同一原子预算文件，并在单个桌面进程内按目录/项目串行更新；同进程的 Repository 实例共用队列。任务额度、模型结算和工作区修改也使用该更新边界。

文件落盘与网络发送不是同一事务，所以请求数是已预留尝试的保守上界。预留后崩溃、取消或不能确认发送结果时不自动退款；重试必须新建 reservation。未获预留的请求不会发往配置的上游。provider 的重定向不会由产品客户端自动跟随。

同一 reservation 相同 usage 的重复结算只读返回，不重复累加；不同 usage 或结算状态被拒绝。独占应用启动时把遗留 reserved 记录一次性结算为 interrupted/unknown，保留请求次数，不重新调用 provider。不能在另一个有效请求仍可结算时调用启动恢复。

任务次数只在启动新执行器前检查，不能因当前任务用了最后一次额度而禁止它内部的模型调用。同样，最后一份模型预留允许响应正常返回、结算和提交合法任务结果；下一次模型请求才会因额度不足被拒绝。预算拒绝暂停项目并返回 budget-exhausted，不作为模型任务失败消耗重试。

## Token 与费用的边界

total-only usage 可单独累计；没有 total 时，仅在 input/output 都有值时能得到完整总量。部分 usage 保留已知值，同时计为未知总用量。缓存 token 明细不会额外加到 total 中。无效、缺失或无法在有界解析区间内读取的 usage 保持 unknown。

token 上限是基于已报告 usage 的停止阈值，不能精确限制在途请求、输入 token、缺失 usage 或服务端实际账单。已批准的单请求可能超过阈值；SDK 代理另限制每次输出 token。工作区明确显示未知和待结算次数，不能把 unknown 当作零成本。

搜索、OCR、embedding 的调用和费用暂不属于本账本，界面明确说明另计。没有价格来源时不编造货币费用。

## 规划、SDK 和工作区

创建项目先保存初始项目与预算，再调用规划器。规划失败仍有可查看项目和停止原因，没有计划时不伪造一份成功计划。重新规划在锁外等待 provider，提交前复核项目/计划状态，避免嵌套获取预算锁和过期计划覆盖。

规划来源在计划中标为 provided/model/default/fallback。一般 provider/无效输出错误可使用有记录的默认计划；预算耗尽、取消和预算存储错误不静默降级。验收脚本启用 strictPlanning，禁止将默认计划冒充真实模型规划。

自动研究 SDK 使用父进程的认证 loopback 代理：随机端口/路径/token，固定上游，拒绝 Origin、错误认证和非约定路径。子进程过滤继承和显式传入的 provider 凭据，模型路由仅注入代理 token；真实 provider key 留在父进程。只转发明确允许的请求 headers，错误响应不回显上游正文。任务取消、墙钟/任务超时及正常关闭均取消在途上游并结算。

工作区提供请求额度、已报告 token 阈值、已用/未知/待结算显示。修改需要可信窗口 IPC；桥与模型没有增加额度接口。仍在运行或有待结算请求时拒绝修改。保存保留用量和首次执行时间，项目不会自动恢复。

## v1 升级

v1 预算继续只读兼容，不能据此启动自动研究。必须在工作区明确配置模型请求及 token 限制才升级到 v2；读取、重启和 replan 都不会赠送额度。升级保留任务计数、首次时间和 revision，标记 `unmeteredHistory: true`，明确历史模型用量未计量。预算文件缺失同样需要显式配置，不推断历史用量为零。
