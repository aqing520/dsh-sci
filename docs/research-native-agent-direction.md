# 在主 Agent 中实现科研能力

日期：2026-11-03。状态：底层主对话链路已实施并进入验证；证据直达呈现与真实模型科研质量验收继续推进。实现和验证范围见[主对话科研实现](research-conversation.md)。依据：[Rewind 逆向与源码对照](../research/rewind-analysis-report.md)。

## 产品目标

用户在现有 DSH 对话中提出研究问题，Agent 就能寻找和阅读资料、区分主张与证据、提出可检验的比较、编写和执行实验、解释不确定性，并根据结果继续推进。用户无需先打开 Research Workspace、建计划、激活任务、启动另一个 Agent。

科研能力由工具、上下文、执行和验证共同提供。页面展示这些能力产生的状态，不承担能力的定义。

不把所有问题强塞进固定七阶段：论文解读可以只用阅读和证据；小型复现可以从代码与实验开始；开放问题才需要长期计划。Agent 按问题选择动作，并明确已经读到、跑到和验证到哪一步。

## 目标链路

```text
用户与当前 DSH Agent 对话
  → 当前 session 的 workspace / 研究上下文
  → 按需科研工具和上下文检索
  → ResearchOrchestrator / Repository
      ├─ 来源、正文、引用、主张、反证
      ├─ 假设、设计、代码和输入版本
      ├─ 实验运行、输出、指标和不确定性
      └─ 检查点、预算、记忆和恢复
  → 当前对话中的解释、证据链接和必要审阅
```

同一会话复用当前 DSH provider/模型 adapter 和凭据引用。研究对象保存在后台，但后台不等于隐瞒执行、预算或数据去向。

## 迁移顺序

### 1. 打通当前会话

- Harness 插件提供 session 绑定服务，以稳定 session/workspace 身份定位研究项目。普通问答无需完整项目；需要持续研究时，通过对话工具建立或恢复。
- 主对话取消对全局 active-context.json 的 fallback，旧记录提供迁移。外部 runner 的隔离上下文保留作兼容入口。
- 复用当前模型和 credentials 服务。科研动作不应因外部 runner 只会 /responses 而拒绝官方 DeepSeek。
- 在现有模型请求生命周期中接入任务/请求/usage 计量；缺 usage 记录 unknown，保留用户授权的预算边界。不能为兼容模型直接跳过预算。
- 内核通过工具/宿主提交带版本的收据，用户读正常解释，不再要求最终回答是内部 task-result JSON。

第一条纵向用例：在原对话里“比较这两篇论文的方法和证据”。从正文读取到保留引用、输出比较全部完成，无需另开页面或第二个可见 Agent。

### 2. 提供可准确调用的科研工具

现有 research_action 可以保留作内部兼容层，对模型优先暴露明确、分组且有输入 schema 的工具。

| 能力 | Agent 行为 | 内核保证 |
| --- | --- | --- |
| 文献 | 搜索、识别来源、读取和定位正文 | 来源身份、版本、读取记录、引用位置 |
| 证据 | 保存主张及支持/反驳/限定关系 | 引用可追溯；摘要不能冒充全文阅读 |
| 实验 | 设计对照、准备代码和输入、请求执行 | 设计与代码版本绑定，运行和输出真实记录 |
| 分析 | 读取结果、计算指标、解释不确定性 | 记录算法与输入，不把静态审查说成测试通过 |
| 持续研究 | 恢复进展、检索记忆、调整下一步 | 按 session/workspace 隔离，保留冲突和历史 |

工具返回与下一步有关的内容和游标，避免反复读全项目 JSON。校验沿用现有内核，不在 UI 或插件里重写一套。

### 3. 在 Agent 生命周期中推进研究

- system-prompt/assemble：按当前问题加载研究目标、相关证据、最近实验和未解决问题，附来源与新鲜度，不能把记忆当确定事实。
- 请求/步骤边界：检查预算、取消、能力和任务状态；合理压缩上下文，限制无进展重试。依据当前 DSH 公开 hooks 实现，不改官方依赖源码。
- 工具完成：内核保存收据及证据关联，再更新下一步，不凭模型一句“完成”推进全部状态。
- 结束/中断：保存可恢复检查点，下次同 workspace 对话按需恢复，不重复实验、不自动扩预算。
- 复杂任务可在后台用 runner，但调度、取消、进度和结果归属于发起的对话，不再要求用户手动管理第二套工作台。

只增加 prompt 不足以完成这一步；也不要把七阶段表单换成隐藏在后台的同一套强制流程。

### 4. 审阅在对话附近按需出现

复用现有来源、设计、代码、报告审阅能力，通过对话中的证据链接打开。当前独立工作区可以保留为诊断和历史兼容入口，减少迁移风险。

实验需要授权时，展示具体命令、目录、输入、输出和版本，由可信宿主记录授权。可用对话附近的原生确认组件，不要求切到独立窗口；模型生成的“已批准”文字不构成收据。

科学主张的支持程度、实验设计审阅、预算和执行权限是不同问题。不要把每一步都变成相同的审批，按已有授权和具体任务处理。

## 先修复归属

同一 session 的聊天目录、捕获目录、实验目录和研究项目必须一致。两个 workspace 不能因一个全局 active 文件相互串联。旧研究属于原 workspace；切换需建立明确新绑定，不能悄悄搬动已批准实验。

复用既有 plan/version/hash/receipt 和恢复逻辑，不删可追溯机制。明确普通编程工具与受控实验的边界；普通 shell 输出不能自动变成已审阅、已绑定的科研运行。

## 用真实任务验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 默认 provider 在原对话读两篇论文 | 不另开工作区；能读正文、给定位引用、解释方法差异；缺正文明确说明 |
| 搜到论文但未读全文 | 不声称全文支持结论，不伪造正文引用 |
| 小型可复现实验 | 当前对话给出对照与指标，经具体授权执行，保存代码/输入/输出版本并解释不确定性 |
| 实验反驳原假设 | 呈现反证并修订判断，不倒改原预测 |
| 中断后恢复 | 恢复同一研究，旧实验不重复跑，未提交工作不冒充完成 |
| 切 workspace 或使用两个会话 | 上下文、记忆、快照、执行目录正确隔离 |
| 切模型或更新凭据 | 下一次科研动作使用当前配置，不继续用启动时缓存 |

质量评估检查产物本身：证据是否支持主张、比较是否公平、实验是否可复现、不确定性是否诚实。工具调用、schema 和 UI smoke 通过只证明基础链路，不能证明 Agent 会科研。
