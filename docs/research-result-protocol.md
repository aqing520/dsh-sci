# 研究任务结果协议与提交恢复

2026-10-30，P1.4。该协议约束研究任务结果的身份、接受与恢复；来源正文质量、实验设计、报告审阅仍由 P2—P5 验收。

## 当前协议

新计划仍采用 `dsh-sci.research-plan.v1` 存储格式，但声明 `resultProtocol: dsh-sci.research-task-result.v2`。任务增加 `stateVersion` 和 `attemptId`。每次状态转换增加版本，进入运行状态分配执行身份；重新调用执行器处理仍在运行的任务时也更新身份，避免取消/重启前的旧响应混入新调用。

结果必须携带：

| 字段 | 来源与约束 |
| --- | --- |
| projectId / taskId | 当前项目和任务 |
| planId | 当前计划 ID；任务名相同也不能跨计划提交 |
| attemptId | 当前运行的执行身份；失败重试、重新调用执行器会变化 |
| expectedTaskVersion | 提交前的任务状态版本，必须精确匹配 |
| submissionId | 一份不可变结果的唯一 ID；SDK 提示建议使用 `result-<attemptId>` |

SDK 提示和 bridge `context.resultIdentity` 提供完整身份。模型必须原样复制；内核不会给缺失身份的旧结果补字段。旧结果及计划仍能作为历史文件读取，但旧结果不能写入当前执行，旧计划缺协议/状态字段时需明确重新规划。

结果的 refs 保存已登记记录 ID，claims/evidence 保存新对象。先校验引用、证据目标、任务范围和完成契约，再接受提交。已完成任务上的相同提交返回原收据结果；相同 ID、不同内容拒绝。之前已经接受的旧计划提交可只读返回收据，不再改写当前计划；从未接受的旧计划/旧执行结果拒绝。

## 接受与恢复

1. 解析结果并验证身份、全部引用和结构完成条件。
2. 在内存中确定主张/证据 ID、最终任务/项目状态、事件 ID 和上下文。
3. 保存 `prepared` 提交日志，作为接受点；此前不写本次结果的新研究记录。
4. 按日志写主张、证据、计划、项目、事件和上下文；重放使用原 ID，事件按 ID 去重。
5. 最后把日志保存为 `committed`。同 ID 的重试返回最初接受的结果和时间。

日志位于项目的 `result-commits/<SHA256(submissionId)>.json`，使用 Repository 既有的原子替换及可选 AES-256-GCM 元数据加密。日志包含结果内容及恢复需要的记录，不属于只保存动作类别的 bridge 安全审计；不可把未脱敏的整个研究目录直接作为公开诊断包。

应用独占启动时先恢复已接受结果，再处理 interrupted 实验；Runner 开始执行和编排器的串行状态变更也先恢复。保存中断使 Runner 返回 blocked，不把持久化故障误记成模型失败，也不为此重新执行实验。尚未成功保存接受日志时，新调用仍需重新执行任务并消耗一次预留额度。

恢复校验日志 schema、项目/计划、请求内容哈希、记录数量、最终任务状态和当前执行版本。损坏日志、错误文件名、跨项目内容或执行状态不匹配都会阻止继续执行，不静默跳过或重置。恢复只写已经接受的研究数据，不调用模型、搜索或实验命令。

## 已验证与边界

- 并发/顺序重复提交、重建 Repository 后重试，主张/证据/完成事件保持唯一；同 ID 修改内容被拒绝。
- 无身份、旧计划、旧执行、旧状态版本不能产生本次结果的研究记录；旧执行器的结果或异常不会把同名新任务标为失败。
- 接受日志、主张、证据、计划、项目、事件及最终收据七处写入后注入故障，恢复无重复记录、无额外执行器调用、无额外任务额度。
- 实际子进程在第一条主张写入后以 exit 37 退出；明文及加密目录均能在新进程所有者中恢复，保留唯一完成事件。
- 覆盖 failed/blocked/needs-approval 三种结果的重复提交、接受前保存失败后的新执行身份及损坏日志拒绝。

此实现依赖现有的桌面单写入者和项目内串行化。它提供进程崩溃后的日志重放，不提供多个独立进程同时修改同一目录的事务协调，也不宣称多文件读取具备数据库快照隔离或已经验证断电落盘语义。模型通过其他工具预先保存的记录不属于结果日志事务；工具调用自身的去重和权限边界仍按各工具单独处理。

本轮 [验证记录](../research/validation/research-result-protocol-1793298974897.json) 包含构建、151 项测试（150 通过、1 项 Windows 权限跳过）及五类 smoke，不能据此宣称完整真实科研案例或科研结论质量已通过。P1.5 现已接入产品级模型请求预算及规划调用计量，见 [模型预算](research-model-budget.md)；P1.6 真实科研复验仍独立验收。
