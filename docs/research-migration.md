# 研究数据离线迁移

迁移对象是 ResearchRepository 的研究根目录，包含项目、计划、预算、来源正文、阅读记录、审阅、运行记录、报告和记忆。此命令不迁移 capture 元数据，也不安装或升级应用程序。

先关闭桌面应用、SDK 和所有会写该根目录的脚本。目标父目录必须存在，目标目录尚不存在。加密记录继续使用原来的 `DSH_SCI_METADATA_PASSPHRASE`，不要把密码写入命令行或提交到仓库。

```text
npm run research:store:migrate -- --source D:/closed-data/research --target D:/closed-data/research-next
```

命令会创建以下内容：

- 原 research 目录始终保留，迁移不写入源文件。
- `<target>.migration/before` 保存按路径、长度和 SHA-256 校验的完整原始副本。
- `<target>.migration/journal.json` 记录源快照及提交阶段；配置密码时 journal 和结果记录加密。
- 独立阶段目录用于校验、重建派生项目索引和恢复已持久化日志。成功后原子 rename 为目标目录，并保存格式标记。

成功输出 `ok: true`，目标目录成为可打开的新研究根目录。当前桌面应用仍使用其 userData 下 `capture/research` 固定路径；不会自动切换到目标。切换前关闭所有进程，保留原目录与迁移副本，再由操作者替换研究目录。安装版迁移入口和升级流程尚待验收。本轮没有对用户研究数据执行迁移或切换。

中断后使用完全相同的 source 和 target 重跑。若源快照、备份或 journal 已改变则拒绝；部分阶段保留用于诊断，重试基于原始备份新建阶段。成功后重复执行只核对同一迁移身份并返回原结果，不改写目标中的后续研究记录。已发布目标丢失、目标属于另一迁移或备份损坏时不会覆盖或自动重新生成。

旧格式的兼容门槛仍然生效：缺少执行身份和完成契约的计划要求复核/重新规划；V1 预算保留历史计数并要求显式配置模型额度；旧报告只能按当前证据作为草稿/过期版本查看，不能沿用存储的 reviewed 标签。中断实验标记为 interrupted 并暂停项目，不自动重跑；尚未结算的模型请求标记为未知用量，不把未知成本记为零。

损坏的派生项目索引从项目主记录重建；损坏的预算、正文、已提交 JSON/JSONL、记忆索引或加密记录会阻止发布。发现 `.tmp` 文件时也会阻止迁移，保留源目录供人工检查；不自行删除半写文件或推断其已提交。未知/未来格式拒绝降级读取。使用旧程序时应恢复原目录或 `before` 副本，不能假定旧程序支持新数据。若旧索引本身损坏，恢复副本忠实保留这一损坏，不承诺旧程序可以直接列出项目。

代码暂存、实验输入、产物文件和外部依赖常位于工作区，记录中仍绑定原路径；迁移不会复制或重写研究根目录以外的内容。更换电脑/工作区后需要另行恢复这些文件并重新核验版本，不能沿用失效审批。备份不会把原本明文的文件全部转换为加密，工具不承担密码轮换或明文转密文。

当前限制为 50,000 个文件、单文件 128 MiB、一个快照总计 1 GiB。目录必须为常规目录，拒绝 symlink/junction；源、目标及迁移控制目录不得重叠。迁移要求独占离线使用：哈希检查能发现观察到的改动，不能代替跨进程文件锁，也未证明断电时 fsync 持久性。Windows 安装版升级、Linux 和真实科研质量另行验收。
