# 科研 Agent 真实案例验收协议

协议：`imputation-v1`，2026-10-30 冻结。机器可读输入见 [imputation-v1.json](../research/benchmarks/imputation-v1.json)。每次运行保存原始协议副本及 SHA-256；修改研究问题、数据规则或指标必须升级协议，旧运行保留。

## 研究问题与边界

在 MCAR 缺失机制下，均值和中位数插补恢复有偏分布数据的误差有何差异？改变损失函数或数据分布会怎样？

使用独立模拟数据，不涉及真实个人数据。结论只能适用于明确的分布、MCAR、缺失率与评价方式，不泛化为临床或所有缺失数据的处理建议。不提前指定胜出方法；MSE 与 MAE 的理论目标不同，不能挑选有利指标后宣称普遍更优。

## 预先固定的设计

- 每次模拟 2,000 个值，100 个独立重复；分布为标准正态及由标准正态取指数得到的对数正态。
- 缺失率 10%、30%、50%。掩码独立于数值，两个方法使用相同数据与掩码；插补参数只从未缺失值估计，真值只用于评分。
- 基础种子 20261030，mulberry32 + Box–Muller；每个条件/重复记录独立数据流与掩码流种子。实际实现须保存且经审批，不以算法名称代替代码版本。
- 主条件固定为对数正态、30% 缺失；主指标为缺失位置的 MSE，次指标 MAE 仅作探索性说明。
- 以独立重复为分析单位，方法之间配对；比较 MSE(mean) − MSE(median)，不能把同次模拟中的缺失单元当独立样本。
- 95% 区间用配对重复差值的 percentile bootstrap，10,000 次重采样，固定记录 bootstrap 种子；同时报告原始差值和相对差值，实际效应门槛为 2%。
- 其他分布和缺失率是探索性稳健性检查，不作未校正的多重确认性检验。
- 正态分布检查适用范围，不强制“无差异”。额外 8 次重复构成证据不足对照，少于 30 次按预定规则必须 inconclusive/review；不因区间看似有利忽略该规则。
- 最多 2 轮研究迭代；不得按有利结果反复追加实验或事后更换主指标。

## 自动化运行与人工介入

运行 `npm run research:case:check` 只检查冻结协议与脚本入口，不调用模型。`npm run research:case:live` 调用应用实际配置的真实 provider，会消耗 token，并可能使用已配置的独立搜索服务。

真实模式首先调用模型规划器，再通过官方 DSH SDK 执行生成的研究计划；不手写研究结论、假设或任务结果。不自动批准任务或执行模型提出的命令；遇到审批后保存轨迹并停止，后续需独立审阅。开始 URL 是人工提供的检索线索，运行记录明确区分其与自主检索。

预算固定：最多 32 次上游模型请求、12 次任务执行、每任务最多 12 个模型步骤、每任务 120 秒、总计 12 分钟；单响应最多 6,144 output tokens。重试也计入请求。保存可获得的 token usage，缺失为 unknown；没有价格信息就不编造费用。两次历史基线由验收代理控制请求次数。P1.5 后，产品内核已统一接入规划和 SDK 请求预留/结算，案例把请求、任务和时间额度传给产品，验收代理保留作独立观测；两者计数需在新运行中核对。最新 resourceConfiguration v2 另设 1,000,000 已报告 token 停止阈值，旧运行没有该产品阈值，不作同资源性能比较。旧基线不能验证这些新增接线。

## 证据包与成功标准

每轮目录 `research/validation/cases/<case-id>-<timestamp>/`：

- `protocol.json`：运行前冻结的精确输入；`summary.json` 保存哈希、版本、状态、预算、模型调用和阶段覆盖。
- `plan.json`：模型实际产生的计划；`snapshot.json`：脱敏后的研究记录；`trace.json`：研究事件、任务结果及人工动作。
- `runtime/`：隔离 SDK home、工作目录、原始 Repository；仅本机诊断，Git 忽略，不将可能含敏感错误的原始 SDK 会话当公开证据提交。

机器记录“完成了哪些步骤”与“科研质量通过”分开。来源/引用数量只能表明存在记录，不能证明阅读忠实度。完整通过仍需人工核查至少 3 个独立相关来源、引用支持关系、预定实验和统计解释，以及报告到来源/产物链路、新会话记忆。

P0 的退出条件是有真实基线轨迹、可定位失败点和修复清单。waiting-approval、blocked 或明确失败允许成为 P0 基线结果，但都不等于完整科研案例通过。所有失败运行保留；修复后重跑使用新目录，不覆盖旧证据。

## 后续阶段验收

统计内核现在默认使用 `dsh-sci.bootstrap.v2`：零种子不再被替换，种子范围明确为 uint32。输入可显式指定 `version: "dsh-sci.bootstrap.v1"` 重放历史算法（包括旧的零种子替代与大整数截断）。新评估把版本同时保存在输入和计算结果中；已有评估仅在计算结果内保存版本时，重新评估会沿用该版本，版本冲突会拒绝。读取不会迁移或改写旧结果。BigInt 独立参考区间、旧记录往返和版本边界已覆盖；此内核修复不表示主案例已运行或通过独立复现。
